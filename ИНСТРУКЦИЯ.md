# GridForge — инструкция по работе с сайтом

Практическое руководство «как пользоваться» — для оператора/нового
владельца, не для разработчика. Технические детали (API, curl-примеры,
переменные окружения) — в [README.md](README.md); архивная сводка на
2026-09-25 — в [docs/archive/HANDOFF.md](docs/archive/HANDOFF.md).
Справка о происхождении кода/лицензиях (для продажи) —
[docs/LICENSE-ORIGIN.md](docs/LICENSE-ORIGIN.md).

## 1. Вход

Открыть `http://<адрес сервера>:8100/` в браузере. Три способа войти:

1. **Логин и пароль** — встроенная учётка `Admin`/`gridforge` при первом
   запуске. **Сменить пароль сразу** — страница «Пользователи».
2. **Через домен (AD)** — если настроено администратором, поле логина
   принимает доменную учётку напрямую.
3. **Через SSO (OIDC)** — если настроено, на странице входа появляется
   кнопка «Войти через SSO» (Keycloak/Azure AD/Google Workspace и т.п.).

Для программ/интеграций — отдельный **API-ключ** (шапка сайта, поле
«X-API-Key»), не то же самое, что пароль человека.

**Роли**: `viewer` — только смотреть; `operator` — плюс запускать
проверки на оборудовании (бэкап, аудит, скан, захват трафика);
`admin` — плюс менять настройки, инвентарь, выдавать ключи/пользователей.
Пользователя можно ограничить одной группой узлов — тогда чужие узлы он
просто не увидит.

## 2. С чего начать — первые шаги

1. **Инвентарь → Группы**: завести хотя бы одну группу (например, по
   зданию/площадке).
2. **Инвентарь → Узлы**: добавить узел — имя, IP-адрес, группа,
   опционально вендор (Cisco/Juniper) — вендор нужен, если планируется
   заходить на устройство по SSH (бэкапы, Рубка, Сценарии).
3. На узле — **«+ проверка»**: выбрать тип (пинг, TCP-порт, SSH-команда,
   SNMP) и параметры. Проверка стартует сама по расписанию (интервал
   задаётся при создании).
4. На проверке — **«+ условие»** (Watch): когда считать это проблемой
   («проверка провалилась 3 раза подряд» и т.п.) и насколько это
   критично (info/warning/critical).
5. **Каналы уведомлений**: завести канал (Telegram/webhook/Apprise —
   см. §7), чтобы про новые проблемы приходило сообщение, а не только
   появлялась запись на Дашборде.

После этого узел уже полноценно мониторится — Дашборд покажет его
состояние, при проблеме придёт уведомление.

## 3. Дашборд

Открытые проблемы (Incident) по всей сети, обновляется каждые 5 секунд.
Здесь смотреть в первую очередь — «что сейчас не так».

## 4. Раздел «Сеть» — повседневная работа с оборудованием

- **Инвентарь** — узлы, группы, проверки, условия (см. §2). Здесь же
  подсказки: «эти узлы одного вендора без группы — объединить?» и «этот
  узел не отвечает N дней — заархивировать?» — появляются сами, когда
  есть что предложить, применяются одной кнопкой.
- **Шаблоны** — готовый набор проверок+условий, который можно применить
  к узлу одной кнопкой (не заводить руками каждый раз для однотипных
  устройств).
- **Рубка** — одна **читающая** команда сразу на группу узлов (посмотреть
  что-то на всех коммутаторах разом). Ничего не меняет на устройстве —
  список разрешённых команд ограничен намеренно.
- **Сценарии** — массовая **смена** настроек на группе узлов (NTP,
  баннер, AAA и т.п.). В отличие от Рубки — реально меняет конфигурацию,
  поэтому набор сценариев фиксированный, заводит администратор заранее,
  не произвольный ввод.
- **Порты** — схема портов коммутатора по последнему опросу (не
  автообновляется — рядом всегда время последнего снимка). Тут же
  Port Security и защита от петель (STP), включаются кнопкой.
- **Консоль** — интерактивный SSH прямо в браузере, как обычный
  терминал.
- **Команды** — справочник команд по вендорам для человека (сюда ничего
  не выполняется — только посмотреть, как что называется у Cisco/Juniper).
- **Версии ПО** — каталог файлов прошивок/образов. Сама заливка на
  устройство — вручную (TFTP/консоль), это только хранилище.

## 5. Раздел «Состояние» — что происходит на сети

- **Бэкапы** — снимок конфигурации узла по кнопке (не автоматом),
  история и сравнение с предыдущей версией одним кликом.
- **Аудит** — свои правила «в конфиге должно/не должно быть такое-то»,
  проверяются по последнему бэкапу.
- **Поиск по конфигу** — grep по самому свежему бэкапу каждого узла
  сразу, по всему парку одним запросом.
- **Вероятные хабы** — находит подозрительные порты (несколько разных
  устройств на одном access-порту — возможно, воткнут неучтённый хаб).
- **Поиск MAC** — где физически подключено устройство по его MAC-адресу,
  по всему парку разом.
- **Домен** — инвентаризация Windows-станций в сети (кто залогинен,
  какая ОС) через WinRM/SMB.
- **Syslog** — принятые логи с сетевых устройств (порт 5140, настроить
  на устройстве отправку именно сюда). Тут же поиск «страна/провайдер
  по внешнему IP» (GeoIP) — см. §7.

## 6. Раздел «Разведка» — поиск и анализ

- **Скан** — nmap-обнаружение живых хостов в подсети, найденное можно в
  один клик завести как Node в инвентаре. Есть плановое сканирование по
  расписанию с оповещением о новых устройствах.
- **Уязвимости** — nmap-проверка на известные уязвимости по группе
  узлов, копится в накопительный отчёт («Отчёт о проведении оценки
  уязвимости сетевых ресурсов»), готов к скачиванию как официальный
  бланк.
- **Кабели** — журнал «откуда куда идёт кабель», для Cisco заполняется
  автоматически через CDP по расписанию.
- **Трафик** — захват пакетов на интерфейсе этой машины по кнопке
  (не mirror-порт коммутатора — увидит только то, что идёт через саму
  машину GridForge).
- **Потоки (NetFlow)** — непрерывный (не разовый) анализ трафика: топ
  «говорящих» узлов и топ пар источник→получатель. Нужно настроить
  экспорт NetFlow v9 на коммутаторе на порт 2055 этого сервера.
- **AD-аудит** — проверки домена Active Directory (в духе PingCastle) —
  устаревшие объекты, привилегированные учётки, доверия, аномалии.
  Сначала завести подключение на странице «LDAP».
- **Аудит сети** — то же самое, но для конфигураций самого сетевого
  оборудования (Cisco/Junos) — управление доступом, резервирование,
  гигиена конфигурации.
- **Спроси про сеть** — задать вопрос обычным языком («какие узлы не
  отвечали дольше суток?») и получить ответ на основе реальных данных
  GridForge, со ссылкой на то, какие записи использовались. Отвечает
  ИИ (Gemini), но доступ у него только на чтение — писать в базу через
  этот раздел невозможно физически, не только по договорённости.
  Нужен настроенный ключ (см. §7).

## 7. Раздел «Настройки»

- **Каналы** — куда уходят уведомления о новых проблемах: Telegram,
  webhook или **Apprise** (один канал — доступ сразу к 80+ сервисам:
  Slack, Discord, email, ntfy и т.д., см. подсказку на странице). Можно
  настроить эскалацию — если проблема висит дольше N минут, уходит
  повторное уведомление в другой канал.
- **Пользователи** — учётки для входа по логину/паролю, роли и
  ограничение по группе.
- **Учётки** — центральные логин/пароль для подключения к сетевым
  устройствам (чтобы не вводить пароль каждый раз при бэкапе/консоли/
  Рубке) — на конкретный узел, на группу, или «по умолчанию».
- **Интеграции** — ключи для внешних сервисов: MaxMind (GeoIP/ASN,
  страна и провайдер для внешних IP), Gemini (для «Спроси про сеть»),
  Graylog/Zabbix (если используются параллельно). Ключ вводится один
  раз, при сохранении сразу проверяется рабочим вызовом, дальше не
  показывается (только факт, что настроено).
- **LDAP** — подключения к контроллерам домена для AD-аудита, можно
  завести несколько доменов сразу.

## 8. Частые вопросы

**Не приходят уведомления** — проверить: у канала не занижен
`min_severity` (например, стоит «только critical», а проблема —
warning); канал не привязан к другому узлу/условию, если ожидали общий.

**Узел показывает «нет данных»** — у него ещё нет ни одной проверки
(Probe), либо проверка есть, но ещё не успела ни разу сработать (смотри
интервал опроса).

**Нужно временно скрыть узел, но не удалять** — «Инвентарь» →
редактировать узел → снять «активен» (или воспользоваться подсказкой
жизненного цикла, если узел давно офлайн, — предложит это само).

**Забыли пароль администратора** — доступ к серверу нужен физически/по
SSH: пароль можно сбросить только напрямую в базе (обратиться к тому,
кто администрирует сервер, не через веб-интерфейс).
