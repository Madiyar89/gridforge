# 001 — Конструктор графиков дашборда

Статус: draft

## Проблема / зачем

Дашборд (`static/index.html`) сейчас показывает снапшот состояния
(счётчики, стена узлов, список инцидентов), но не даёт посмотреть на
метрики во времени рядом друг с другом. Единственный график, который
есть в проекте — мини-график одного `Probe` внутри карточки узла в
`inventory.html` (`renderProbeChart`, SVG-полилиния с порогами watch).

Владелец параллельно поднимал Prometheus+Grafana на отдельном хосте
(192.168.7.243) для этой же задачи. Решение (2026-09-30): не тащить
внешний стек внутрь GridForge и не копировать код/дизайн Grafana —
у GridForge уже есть архитектурный эквивалент time-series-хранилища
(`Probe`+`Sample`+`Watch`, составной индекс `probe_id+taken_at`),
не хватает только UI-слоя для просмотра нескольких графиков вместе.
Требование владельца: всё своё, ничего не копируется — уже закреплено
`tests/test_naming_purity.py`, эта работа его не нарушает (не берём
чужие имена сущностей/API).

## Что делаем (scope)

1. Отдельная страница `graphs.html` — несколько графиков рядом,
   общий временной диапазон (выбор: 1ч/6ч/24ч/7д), возможность
   добавить график по конкретному `Probe` (или нескольким сразу для
   сравнения — например, два узла одного типа).
2. Backend: эндпоинт, отдающий `Sample` за диапазон времени с
   даунсэмплингом при большом объёме точек (чтобы не тянуть в браузер
   десятки тысяч точек за 7 дней) — вынести логику отдельно от уже
   существующего `/api/probes/{id}/samples` (тот — под мини-график в
   инвентаре, `limit`-based, не time-range-based).
3. На дашборде (`index.html`) — вынести уже посчитанный, но не
   используемый `problem_nodes` из `build_dashboard` в панель "Топ
   проблемных узлов" (P0 из исследования агентом 2026-09-30, готовые
   данные простаивают).
4. Стрелка тренда (↑/↓/→) у critical/warning счётчиков — сравнение
   последних 2-3 часов с предыдущими на основе уже существующего
   `/api/dashboard/incident-trend`.

## Что НЕ делаем (out of scope)

- SNMP-метрики трафика/ошибок портов — отдельное ТЗ (002 или 003),
  это сбор новых данных, не только UI.
- Heatmap "узел × час" и разбивка по vendor/группе — следующая
  сессия/следующее ТЗ, не мешаем в одну задачу.
- Retention/downsampling политика хранения `Sample` (чистка старых
  данных) — отдельный вопрос, здесь только downsampling НА ВЫДАЧЕ
  (агрегация в ответе API), не изменение хранения.
- Дизайн/копирование конкретных виджетов Zabbix/Grafana — берём только
  общую идею "несколько графиков рядом с общим диапазоном", верстка и
  код свои.

## API — новые эндпоинты

Черновик, уточнить при реализации:
- `GET /api/probes/{id}/samples/range?since=...&until=...&max_points=...`
  — time-range выборка с даунсэмплингом, отдельно от текущего
  `limit`-based `/api/probes/{id}/samples`.
