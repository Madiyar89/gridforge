# Страница: Бэкапы конфигураций (`static/backups.html`)

## Назначение

Снятие и просмотр бэкапов конфигурации узлов — вручную по одному узлу
или групповым прогоном по всей группе, плюс diff между снимками.

## Данные / API

- `GET /api/nodes`, `GET /api/nodes?group_id=...` — списки для выбора
  узла/группы
- `GET /api/groups` — группы для группового бэкапа
- `POST /api/nodes/{id}/backup` — снять бэкап (команда, логин, ключ,
  порт — через `apiWithCredentials`, не в открытом виде в обычном
  `api()`)
- `GET /api/nodes/{id}/backups` — история снимков конкретного узла
- `GET /api/backups/{id}/diff` — разница между снимками

## Что на странице (UI)

- Панель "Групповой бэкап" — команда + группа, прогоняет
  `POST /api/nodes/{id}/backup` по очереди для каждого узла группы,
  живой статус "N/M — имя узла…", итог "снято X, изменилось Y, ошибок Z"
- Выбор конкретного узла → форма "Снять новый бэкап" (логин, ключ,
  порт, команда — подбор команды по вендору узла) + "История"
  (список снимков со статусом: ошибка/изменился/без изменений, кнопка
  просмотра diff)

## Известные пробелы (по коду, не оценочно)

- Групповой бэкап — последовательный цикл на клиенте (`for` с `await`
  внутри), не параллельный и не серверная задача — на большой группе
  UI держит статус только пока открыта вкладка, обновляется по одному
  узлу за раз
- Нет отдельного эндпоинта "бэкап по группе" на backend — вся логика
  групповой прогонки в JS, backend видит N отдельных вызовов
  `POST /api/nodes/{id}/backup`
