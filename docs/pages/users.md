# Страница: Пользователи и ключи API (`static/users.html`)

## Назначение

Управление пользователями GridForge и их API-ключами (`ApiKey`,
`ApiKeyRole`: viewer/operator/admin), включая привязку к группе
(`Principal.group_id` — область видимости).

## Данные / API

- `GET/POST/PUT/DELETE /api/users` — CRUD пользователей
- `POST /api/users/{id}/password` — смена пароля
- `GET/POST /api/api-keys` — список/создание ключей
- `POST /api/api-keys/{id}/revoke` — отзыв ключа

## Что на странице (UI)

- Список пользователей, создание/редактирование/удаление, смена пароля
- Список API-ключей, создание, отзыв

## Известные пробелы (по коду, не оценочно)

- Доступ к этой странице сам по себе, вероятно, требует роли `admin`
  (по общему паттерну `api_write`-роутера в проекте) — не
  перепроверялось построчно именно для этих эндпоинтов в этом разборе.
- Не проверено, есть ли аудит-лог именно по действиям над
  пользователями/ключами (в отличие от `audit.html`, который про
  конфиги узлов, не про действия в самом GridForge).
