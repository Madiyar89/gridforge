# Страница: Инвентарь (`static/inventory.html`)

## Назначение

Центральная страница управления парком: узлы, группы, проверки (Probe),
условия срабатывания (Watch), автодействия (Action), VLAN. Самая
большая по коду страница сайта (`inventory.js` — сотни строк).

## Данные / API

- `GET/POST /api/groups` — группы узлов
- `GET /api/nodes`, `POST /api/nodes`, `PATCH /api/nodes/{id}` — CRUD
  узлов
- `POST /api/probes` — добавить проверку на узел (см. `ProbeKind`:
  icmp_ping/tcp_port/ssh_command/snmp_get/snmp_walk/snmp_counter_rate)
- `GET /api/probes/{id}/samples` — мини-график пробы (`limit`-based,
  не time-range — см. 001, там же `renderProbeChart`)
- `GET /api/probes/{id}/watches` — условия срабатывания под конкретной
  проверкой
- `POST /api/watches` — создать условие (порог/оператор/severity)
- `GET /api/credentials` — учётки для форм (не сами секреты)
- `POST /api/actions` — авто-действие при срабатывании Watch
- `POST /api/scans` — быстрый inline-скан подсети прямо с этой
  страницы ("+ добавить как узел" из результатов), не через отдельную
  страницу `scan.html`
- `GET /api/lifecycle/suggestions` — подсказки по обслуживанию парка
  (группировка по вендору без группы, архивация давно не отвечающих
  узлов) — сам эндпоинт только читает, применение подсказки — обычные
  `POST /api/groups`/`PATCH /api/nodes`
- `GET/POST /api/vlans` — учёт VLAN и утилизации адресов

## Что на странице (UI)

- Список узлов с фильтром по группе, карточка узла разворачивается в
  список Probe с мини-графиками и Watch
- Форма добавления узла, группы, проверки, условия, действия
- Панель быстрого скана подсети (CIDR + порты)
- Панель подсказок по обслуживанию парка (lifecycle)
- Раздел VLAN с утилизацией адресного пространства

## Известные пробелы (по коду, не оценочно)

- `renderProbeChart` — фиксированный SVG 600×90, только один Probe за
  раз, `limit`-based (последние N точек, не диапазон времени) — 001
  выносит полноценные графики на отдельную страницу, но саму эту
  мини-версию не трогает (разные задачи: быстрый взгляд в карточке
  узла vs полноценный дашборд)
- Быстрый скан на этой странице (`POST /api/scans`) и полноценная
  страница `scan.html` (с историей сканов, плановым сканированием) —
  два входа в один и тот же эндпоинт с разным UI-контекстом, не баг,
  но при правках `/api/scans` нужно проверять оба места
