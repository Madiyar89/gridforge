# Страница: Аудит конфигураций сети (`static/network-audit.html`)

## Назначение

Флот-отчёт безопасности по всем узлам Cisco/Junos с бэкапом — 31
зашитое правило (не пользовательские `AuditRule`, как на `audit.html`),
риск-скор по категориям. Бесстейтовый и синхронный: работает по уже
снятым `Backup.content`, сетевого I/O не делает — в отличие от
AD-аудита, `await` не нужен (см. комментарий `app/main.py:2402`).

## Данные / API

- `GET /api/network-audit/report` — единственный эндпоинт этой страницы,
  весь отчёт одним запросом (`app/network_audit_engine.py:
  build_network_audit_fleet_report`)

## Что на странице (UI)

- Панель `net-report-fleet` — сводный отчёт по всему парку
- Панель `net-report-domain` (скрыта по умолчанию) — детализация по
  конкретному домену/узлу, с кнопкой "← ко всем устройствам"

## Известные пробелы (по коду, не оценочно)

- Только Cisco/Junos — другие вендоры (H3C и т.п.) не покрыты этими 31
  правилом
- Отчёт зависит от актуальности `Backup.content` — если у узла нет
  свежего бэкапа, правила по нему не проверяются (не видно явного
  предупреждения об этом на UI, тот же паттерн, что на `audit.html`)
- Название страницы ("Аудит конфигураций сети") очень похоже на
  `audit.html` ("Аудит конфигураций") — разные механизмы (31 зашитое
  правило vs собственные `AuditRule`), путаница по имени возможна
