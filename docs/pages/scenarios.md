# Страница: Сценарии (`static/scenarios.html`)

## Назначение

Многошаговые сценарии автоматизации (последовательности действий) —
судя по названию и наличию `scenario-runs`, что-то более сложное, чем
разовая "рубка" (rubka), с историей прогонов каждого сценария.

## Данные / API

- `GET/POST/PUT/DELETE /api/scenarios` — CRUD сценариев
- `GET /api/scenario-runs/{id}` — результат конкретного прогона
- `GET /api/scenario-runs?limit=...` — история прогонов

## Что на странице (UI)

- Список сценариев, создание/редактирование/удаление
- Запуск сценария, история прогонов, результат конкретного прогона

## Известные пробелы (по коду, не оценочно)

- Внутренняя структура шага сценария (что можно сделать одним шагом —
  команда, ожидание, условие и т.п.) не разбиралась в этом проходе;
  требует чтения соответствующей модели/движка отдельно.
- Пересечение по смыслу с `rubka.html` (тоже прогон команд по узлам) и
  `templates.html` (применение шаблонов конфигурации) не выяснено —
  неясно, использует ли сценарий эти механизмы как шаги или это три
  независимых системы автоматизации.
