# Страница: Шаблоны конфигурации (`static/templates.html`)

## Назначение

Хранение и применение шаблонов конфигурации к узлам (генерация
конфига по шаблону + переменным, отправка на устройство).

## Данные / API

- `GET/POST/PUT/DELETE /api/templates` — CRUD шаблонов
- `POST /api/templates/{id}/apply` — применить шаблон к узлу(ам)

## Что на странице (UI)

- Список шаблонов, редактор шаблона
- Применение шаблона к выбранному узлу/узлам

## Известные пробелы (по коду, не оценочно)

- Язык шаблонизации (Jinja2 и т.п.) и механизм подстановки переменных
  не проверялись в этом разборе.
- Не проверено, идёт ли `apply` через `asyncssh` напрямую (как
  `rubka`/`console`) или иным путём, и есть ли dry-run/предпросмотр
  перед реальной отправкой на устройство.
