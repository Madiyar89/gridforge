# Страница: Прошивки (`static/firmware.html`)

## Назначение

Хранилище файлов прошивок для загрузки на узлы (загрузка в GridForge,
затем раздача узлам, а не прямой апгрейд "по кнопке").

## Данные / API

- `GET /api/firmware` — список файлов
- `POST /api/firmware` (upload) — загрузка нового файла
- `GET /api/firmware/{id}/download` — скачивание

Точные пути взяты из общей инвентаризации API по странице
(`app/main.py:1456`/`:1464`/`:1475` в заметках по предыдущему разбору) —
конкретные подписи параметров не перепроверялись построчно в этом
проходе.

## Что на странице (UI)

- Список файлов прошивок, загрузка, скачивание

## Известные пробелы (по коду, не оценочно)

- Не проверено, есть ли привязка файла прошивки к конкретной
  модели/вендору узла на уровне данных, или это просто файловое
  хранилище без метаданных совместимости.
- Не проверено, инициирует ли страница реальную заливку прошивки на
  устройство (TFTP/SCP и т.п.) или только хранит файл для последующего
  ручного использования.
