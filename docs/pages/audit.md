# Страница: Аудит конфигураций (`static/audit.html`)

## Назначение

Per-узел проверка running-config на соответствие собственным правилам
(`AuditRule`), плюс "золотой конфиг" (compliance) — правило → список
узлов, которые ему не соответствуют, по всему парку сразу.

## Данные / API

- `GET/POST /api/audit-rules`, `DELETE /api/audit-rules/{id}` — CRUD
  собственных правил аудита
- `GET /api/nodes` — выбор узла для прогона
- `POST /api/nodes/{id}/audit` — прогнать аудит на узле (по последнему
  снятому `Backup.content`, не живым подключением — см. `network-audit`
  для похожей, но флотовой версии)
- `GET /api/nodes/{id}/audit` — уже посчитанные находки без повторного
  прогона
- `GET /api/reports/compliance` — golden-config отчёт: правило → узлы,
  которые ему не соответствуют, по всему парку (`app/compliance_engine.py`,
  те же `AuditRule`, что и per-узел проверка, просто развёрнутые в
  обратную сторону — правило как ключ, не узел)

## Что на странице (UI)

- Панель "Правила" — список собственных правил аудита, добавление/удаление
- Панель "Прогнать аудит" — выбор узла → прогон/просмотр находок
- Панель "Находки" — результат по выбранному узлу
- Отдельный блок — compliance-отчёт по всему парку

## Известные пробелы (по коду, не оценочно)

- Аудит работает по уже снятому `Backup.content` — если бэкап устарел,
  аудит проверяет старую конфигурацию, не текущую; отдельного
  предупреждения об этом на UI не видно
- `network-audit.html` — параллельная, но другая проверка (31
  зашитое правило, риск-скор по категориям, только Cisco/Junos) — не
  дублирует эту страницу, но легко перепутать по названию
